# レビュー: 「なるなる DAY0」分析 → SNS縦型ショート演出ルールの体系化

対象: `docs/analysis-narunaru-day0.md`
実測ソース: `scratch/day0_analysis/complete_breakdown.json`（ffmpeg scene detect + transcript, 39 cuts / 74.37s / 30fps）
視点: クリエイティブディレクター／SNS動画アルゴリズム
日付: 2026-08-19

---

## 0. 総評

**強い点。** 素材レイヤの分類（A-roll / B-roll Action / Enactment / Evidence / Archival）と、
BGMを焼き込まない配信戦略の指摘は、この種の分析で最も見落とされる2点で、
どちらも Video OS の実装に直結する。7段構造の切り出しも妥当。

**構造的に欠けている点。** 現状の分析は **「何が起きたか」の記述** であり、
**「なぜ視聴者が残るか」のモデル** になっていない。Video OS に落とすには、
記述を **計算可能な制約** に変換する必要がある。具体的に3つが丸ごと欠落している。

1. **Retention曲線のモデルがない** — hookは0秒の崖しか守っていない。実際の離脱は3点で起きる。
2. **コメント誘発の分析がゼロ** — 分布を決める最重要の一次シグナルなのに、章立てにすらない。
3. **無音・間（ま）の設計がない** — SEは列挙されているが、SEを「置かない」設計が語られていない。

そして最大の問題は次章。**分析文が、自分の実測データと矛盾している。**

## 1. 実測データとの整合性チェック（要修正）

### 1-1. 「同一構図を2.5秒以上続けない」は実測と矛盾する

分析文の断言に対し、実測では **3.0秒以上のカットが4本** ある。

| cut | start | duration | 位置 |
|---|---|---|---|
| 08 | 14.27s | 4.37s | Turning Point 冒頭 |
| 27 | 44.50s | **7.30s** | Philosophy（本作最長） |
| 32 | 56.57s | 3.80s | Goal宣言 |
| 39 | 68.50s | 5.87s | CTA / 走り出しの締め |

しかもこの **7.3秒は、Crisis（どん底）直後の復活宣言に置かれた本作最長のホールド** である。
これは「テンポが緩んだ」のではなく、**意図的な溜め**だ。分析はこれを完全に取りこぼしている。

→ ルールは「2.5秒で切る」ではなく **「セクション別のテンポ包絡（envelope）」** として記述すべき。

### 1-2. テンポは感情に従っている（実測が証明している）

セクション別の平均カット尺（実測）:

| セクション | カット数 | 平均尺 |
|---|---|---|
| Hook + Identity | 2 | 2.17s |
| Past & Stagnation | 5 | 1.99s |
| Turning Point | 5 | **2.39s** |
| **Crisis** | 12 | **1.39s** |
| Philosophy & Goal | 8 | 2.19s |
| Vulnerability & CTA | 7 | 2.00s |

Crisisだけが 1.39s と明確に速い。**全体平均1.91秒は結果であって、ルールではない。**
`avg 1.9s` をそのまま実装すると、機関銃のように均質な「いかにもAI編集」の画になる。
本作の実体は **0.67s〜7.30s、約11倍のダイナミックレンジ** である。

> **法則: テンポは感情を運ぶ。テンポが平坦な編集は、内容が良くてもAI編集に見える。**

これは現状の Video OS の弱点（粗編集v2フィードバックの「シーン連続性なし」）と同じ根に触れる。

### 1-3. 計測手法の限界を明記すべき

39カットは **scene detection の値** であり、分析文が主張する
「同一テイク内 1.15〜1.25倍のパンチイン」は、輝度差が小さいため
**scene detect ではほぼ検出されない**。つまり:

- 実際の **画面変化レート（screen-change rate）は 39 より多い可能性が高い**
- 「平均1.9秒」は画面変化の指標として過小評価されている

→ Video OS の閾値をここから導出する以上、**カット数ではなく
フレーム差分エンベロープ（動き・寄り・テロップ差し替えを含む「変化イベント」）** を
計測単位に変えるべき。分析文には計測手法と既知の取りこぼしを provenance として記録すること。

## 2. Retention: 欠けているモデル

### 2-1. 離脱は3点で起きる（hookは0秒だけではない）

分析文は 0秒の崖しか防御していない。運用上は少なくとも3つの関門がある。

| 関門 | 判定内容 | 本作の防御 |
|---|---|---|
| **T0（0〜1s）** | スクロールを止めるか | 特大黄テロップ＋アタックSE＋笑顔の全身画 |
| **T1（〜3s）** | 「これは自分向けか」の判定 | 「46歳 起業家ランナー」＝属性提示 |
| **T2（7〜12s）** | 「もう趣旨は分かった」離脱 | 過去の挫折へ即座に落とす（4.33s〜） |

さらに 74秒という尺では **T3（30〜45%地点）** が最大の崖になる。
本作はここに **骨折→大怪我→再骨折の三連撃（26.2〜42.8s = 全体の35〜58%）** を置いている。

> **本作最大の設計上の知見はここ。危機クラスタは「ドラマ」ではなく「Retention構造物」であり、
> 統計的な離脱ピークに正確に置かれている。** 分析文はこれをドラマとしてしか読んでいない。

### 2-2. Open loop（未解決の問い）が言語化されていない

「世界一になります！」は **宣言** であって **問い** ではない。宣言だけでは引っ張れない。
実際に効いているのは **主張と信憑性のギャップ** —
「46歳が世界一？ どうやって？」という埋めたくなる穴だ。

> **ルール: Hookは「主張の大きさ ÷ 話者の信憑性」が1より十分大きいときにだけループになる。**
> ギャップが無い（有名人・当然の主張）なら、別のループ装置が要る。

そして本作は、そのギャップを **言葉ではなく証拠で埋める**。
レントゲン写真、血の滲む包帯。これがなければ「世界一になります」はただの誇大広告として離脱される。

> **ルール: 大きな主張には比例した物証を要求する（claim ↔ evidence の比例則）。**
> これは Video OS の `evidence` 素材ロールを「あると良い」から **「Hookが aggressive なら必須」** に格上げする根拠になる。

### 2-3. 完走とループ

74秒は Shorts/TikTok では完走率勝負になる尺。分析文には次が無い。

- **ループ継ぎ目（loop seam）**: 最終カット（競技場を駆け出す, 5.87s）→ 冒頭（砂浜ポーズ）。
  ここを画のトーン・視線方向・SEで繋ぐと、2周目に入りやすくなる。本作は未接続（改善余地）。
- **再Hook間隔**: 「残る理由」を10〜15秒ごとに更新する。本作は結果的に満たしている。

## 3. コメント誘発（分析文に完全欠落）

分布拡大の一次シグナルとして、コメント・シェアは視聴時間と並ぶかそれ以上に重い（運用上の前提。
プラットフォーム別に重みは異なり、公開仕様ではないため **ヒューリスティックとして扱うこと**）。
本作には、意図的かどうかは別として **4つのコメント装置** が実装されている。分析文はどれも拾っていない。

| # | 装置 | 実装箇所 | 誘発するコメント種 |
|---|---|---|---|
| 1 | **検証可能な公開約束** | 「2026年8月 世界マスターズ陸上で世界一」 | 応援 / 期日への言及 / 再訪問 |
| 2 | **連番タイトル（DAY0）** | タイトル自体 | 「DAY1待ってます」＝フォロー転換 |
| 3 | **弱さの自己開示** | 「正直ライバルは強い」 | 励まし（最も低コストで最も出やすい） |
| 4 | **アイデンティティ型CTA** | 「一緒に挑戦していきましょう」 | 自己宣言（「私も○○始めます」） |

**「DAY0」という命名は、それ自体がフォロー装置である。** 0は1を約束する。
これはタイトルに書かれているのに分析されていない、最も費用対効果の高い発見だ。

### 追加提案（本作に無い装置）

- **答えられる具体的な問い**を1つ置く（「46歳、遅すぎると思いますか？」）。
  漠然とした「コメントください」は禁止。**穴を空けて、埋めさせる。**
- **意図的な言い残し** — 視聴者が聞きたくなる情報を1つだけ伏せる（例: 現在の記録）。
- **議論可能な数値** — 目標タイム、年齢記録。数値は意見を呼ぶ。
- **固定コメント前提の設計** — 動画側に伏線、固定コメントで回収。

> **ルール: コメントは乞うものではなく、視聴者が閉じたくなるギャップを開けて発生させる。**

## 4. Vulnerability / 感情ジェットコースター: 記述から計算可能な曲線へ

### 4-1. 効いているのは「弱さの位置」

分析文は Vulnerability を第7章の要素として置いているが、本質は **順序** にある。

本作は **目標宣言（第6章）のあとに弱さ（第7章）** を置いている。これは直感に反する。
普通の編集者は目標宣言で終わらせる。

- 強さで終わる → **称賛**（＝いいね）
- 弱さ＋招待で終わる → **仲間意識**（＝コメント・フォロー・シェア）

> **ルール（status-descent ending）: 最後の15〜20%で話者の地位を意図的に下げ、視聴者と同じ高さに立たせる。**
> 目標宣言で終わらせない。

### 4-2. 感情曲線を blueprint のデータにする

`edit-blueprint.schema.json` の `beat` には既に `story_role` と
`quality_targets.emotion_gradient_min` がある。ここに接続できる。

beat に追加する（提案）:

```yaml
- id: b05_crisis
  label: crisis
  viewer_label: 三度の骨折
  story_role: experience
  emotional_valence: -0.8        # -1.0 .. +1.0
  evidence_required: true         # 谷は物証で裏付ける
  retention_device: escalation_cluster
  tempo_envelope: staccato        # 0.7-1.4s
```

**監査可能な制約:**

- 谷が最低1つ、`valence <= -0.5` で存在すること
- 直前ピークからの落差 `>= 1.0`（**落差が感情であり、絶対値ではない**）
- 谷の beat は `evidence` ロール素材を1つ以上持つこと（言葉だけの不幸は信用されない）
- 回復は **明示的な宣言**であること（「それでも僕は諦めません」＝暗黙の回復では効かない）
- 最終20%以内に `vulnerability` beat が存在すること

### 4-3. 谷が存在しない素材のとき

**捏造してはならない。** 既存の原則「素材にない結果、反応、発言、能力を作らない」を
感情構造にも拡張する。谷が無い素材に危機を演出させない。
代わりに `unresolved-blockers` へ
「この企画には谷が無い。過去の失敗・証拠写真を追加取材する必要がある」と出力し、人間に返す。

## 5. 演出ルールの体系化（Video OS 実装案）

分析文の「実装方針」は5項目の願望リストで、契約になっていない。以下を層で定義する。

### Layer 0 — brief プロファイル

`creative_brief.yaml` に `narrative_mode: personal_challenge`（仮）を追加。
既存の `credibility_first`（講演・証言）とは **相反する** ため、分岐は明示的に。

### Layer 1 — ストーリーアーク・テンプレート（散文ではなくデータ）

`references/creator-challenge-arc.yaml` として beat 列を定義。
比率で持つ（秒で固定しない。60秒でも90秒でも伸縮させる）。

| beat | 尺比率 | story_role | valence | tempo |
|---|---|---|---|---|
| hook_declaration | 2% | hook | +0.9 | — |
| identity_gap | 4% | hook | +0.5 | medium |
| past_struggle | 13% | setup | -0.3 | medium |
| breakthrough | 16% | experience | +0.7 | slow |
| crisis_cluster | 22% | experience | **-0.8** | **staccato** |
| philosophy_goal | 24% | experience | +0.8 | **slow + 最長ホールド** |
| vulnerability_cta | 19% | closing | +0.4 | medium |

### Layer 2 — 素材ロール分類と **証拠素材の取得**

`a_roll` / `b_roll_action` / `enactment` / `evidence_still` / `archival` を
analysis / selects の型に入れる。

**製品上の重要な気づき:** `evidence_still`（レントゲン、包帯、記録スクショ）と `archival`
（過去の大会映像）は **撮影素材フォルダに入っていない**。スマホのカメラロールにある。

→ `design-intent`（インタビュー）に必ず聞く項目を追加する:
「怪我・記録・過去を証明できる写真、スクショ、昔の動画はありますか？」
**これが無いと、この構造は物理的に作れない。** パイプラインの最上流の要件である。

### Layer 3 — テンポ法則

- グローバル平均を目標にしない。**beat ごとの `tempo_envelope`** に従う
- クライマックス直前に **本編最長ホールド** を1つ確保する（本作: 7.3s）
- 計測は cut count ではなく **screen-change event**（カット・パンチイン・テロップ差替・インサート）

### Layer 4 — テロップエンジン（**既存ルールと衝突するので注意**）

`finish-business-short` は「transcriptに同期した日本語フル字幕」「発話より先行させない」
を要求する。**このジャンルには転用できない。**

本作のテロップは **逐語字幕ではなく、削り込んだキーワード**である。だから74秒に収まる。

→ 2モードを型で分ける:

- `caption_mode: full_transcript`（信頼性重視 / 講演・証言）
- `caption_mode: keyword_telop`（創作者ショート）— 発話の要約、発話と同時かわずかに先行

スタイルは感情に紐付ける:

| 種別 | スタイル | 用途 |
|---|---|---|
| `hook` | 黄グラデ＋黒縁、最大サイズ | 冒頭宣言 |
| `damage` | 赤黒グラデ、亀裂装飾 | 骨折・大怪我 |
| `emphasis` | 通常の1.3〜1.5倍 | キーワード |
| `plain` | 白＋黒縁＋影 | 地の文 |

**可読負荷バリデータ**（新規・自動判定可能）:
`文字数 / 表示秒数 <= 約8〜10 字/秒`。超えたらテロップを削るか尺を伸ばす。fail-closed。

### Layer 5 — SE文法（列挙ではなく文法）

`sfx-cues.schema.json` の `semantic_role` を機能クラスで拡張する。

| クラス | 用途 | 制約 |
|---|---|---|
| `impact_attack` | Hook、最重要テロップ | 動画あたり1〜2回まで |
| `whoosh_transition` | カットの継ぎ目を隠す | — |
| `damage_hit` | 負の転換点 | **正のテロップに絶対に当てない** |
| `ui_pop` | 軽い強調 | 密度上限あり |
| `riser_tension` | リビール直前 | riser の後には必ず解決音 |
| `sub_drop` | どん底 | 1動画1回 |
| `silence_gap` | **無音の間** | 下記 |

**分析文にゼロだった最重要項目 — 無音。**

> **ルール: 最大の一言（本作なら「本気になるから楽しいんだ」）の直前に、
> 0.3〜0.8秒の意図的な音の落ち込みを置く。**
> SEを足すことより、SEを抜くことのほうが効く。SE密度の上限も設ける（10秒あたりN回）。

### Layer 6 — 監査ゲート（blueprint / compile を fail させる）

| チェック | 条件 |
|---|---|
| `hook_mute_legible` | 1.2秒以内に、音声なしでも主張が読める |
| `open_loop_declared` | 3秒以内にループ提示、60%以降に解決 |
| `evidence_proportional` | aggressive hook なら `evidence` 素材 >= 1 |
| `emotion_trough_present` | valence <= -0.5 の beat が存在、落差 >= 1.0 |
| `trough_evidenced` | 谷 beat に証拠素材が紐づく |
| `rehook_interval` | 「残る理由」の更新間隔 <= 12秒 |
| `tempo_variance` | セクション間のカット尺分散が下限以上（＝平坦禁止） |
| `climax_hold_present` | 最長ホールドがクライマックス近傍にある |
| `telop_reading_load` | <= 約8〜10 字/秒 |
| `sfx_density` / `silence_before_climax` | 上限内 / 無音あり |
| `vulnerability_in_last_20pct` | 最終20%に弱さの beat |
| `comment_affordance_count` | 型付き列挙から >= 2 |
| `loop_seam` | 末尾→冒頭の接続が評価済み |
| `platform_safe_area` | 下記3プラットフォーム分 |

### Layer 7 — 評価ループ

`review-metrics.schema.json` は既に `emotion / story / rhythm / audio` の tier を持つ。
上記チェックをそこへ流し込む。閾値は全て `provisional` と明記し、
**実際のretentionデータで較正するまで確定値として扱わない。**

## 6. 追加提案

### 6-1. プラットフォーム差分（1本で3配信は雑）

分析文は TikTok / Reels / Shorts を1つの的として扱っているが、別物である。

- **セーフエリアが違う** — Reels は下部UIが高い、TikTok は右レール、Shorts は下部タイトル帯。
  1080x1920 の **プラットフォーム別セーフボックスを型で持ち**、テロップ配置を検証する。
- **重視シグナルが違う（運用上の前提）** — Reels はシェア/送信、TikTok は視聴時間＋コメント、
  Shorts はスワイプ離脱率。**同じ編集で、CTAの狙いだけ差し替える価値がある。**
- **尺の許容が違う** — 74秒は TikTok / Shorts では成立、Reels ではやや長い。

### 6-2. 「広告に見えない」ことの設計

A-roll は砂浜・自然光・手持ち感。**信憑性は粗さから来ている。**

> **ルール: creator-short では過剰な手ブレ補正・過剰なグレーディングをしない。**
> Video OS は「きれいにする」方向に倒れやすいので、明示的に禁止側の制約を置く。

### 6-3. 音声レベル（BGM後乗せ前提の帰結）

BGMを焼き込まないなら、**編集のリズムはビートグリッドではなく発話グリッドで決まる**。

- creator-short は **speech-grid でコンパイルする**（現行のBGM同期コンパイルは使わない。
  既存の「BGM同期破綻」問題を、そもそも回避できる）
- プラットフォーム音源が上に乗る前提で **ヘッドルームを残す**。SEは声より 6〜10dB 下。
  焼き込みのダッキングはしない。

### 6-4. DAY0 を4本目のゴールデンに登録する

戸隠・恵那・fumoto と同格の **人間ゴールデン** として扱う価値がある。
既存3本と違い、これは **縦型SNS・話者主導・感情構造** のゴールデンで、
現行ゴールデンが1本もカバーしていない領域。
`scratch/day0_analysis/` にある実測データはそのまま参照ラベルに使える。

## 7. リスクと限界

1. **n=1。** 1本はフォーミュラではなく仮説である。数値閾値は全て暫定。
   実retentionデータ付きで10〜20本の corpus を作るまで、閾値を固定しないこと。
2. **型化の罠。** これをそのまま焼き込むと、Video OS の出力が全部同じ動画になる。
   アーク・テンポ包絡・テロップスタイルには **意図的な変異スロット** を持たせる。
3. **一番効いている要素は生成できない。** 本作の力は、実際に3回骨折した人間が実在することにある。
   Video OS の仕事は物語を作ることではなく、**素材の中にある真実を発見して並べること**。
   構造が素材に無ければ、埋めるのではなく人間に返す。
4. **アルゴリズムの重み付けは公開仕様ではない。** 本レビューのシグナル優先度は運用上の
   ヒューリスティックであり、検証済みの事実ではない。実測で較正すること。
