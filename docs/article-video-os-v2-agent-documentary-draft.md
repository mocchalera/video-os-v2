# AIに感性を明け渡さない。Video OS v2が試した「編集エージェント」の作り方

「AIに動画を作らせる」という言い方は、いまではそれほど珍しくない。テキストを入れれば映像が生成される。スライドや台本を渡せば、Remotionのような仕組みで動画が組み上がる。生成AIの世界では、動画は「作る」対象として語られることが増えた。

けれど Video OS v2 が向き合っているのは、少し違う問題だ。

それは、すでに撮られてしまった素材である。カメラロールに積み上がった映像、インタビュー、セミナー、家族の記録、PVの断片。撮影した人間には、その場の空気や手触りが残っている。でも編集ソフトを開くと、そこにあるのは大量のファイルと長いタイムラインだ。どこを見ればいいのか、何を残せばいいのか、どの順番に並べれば意味が立ち上がるのか。その判断は、まだかなり人間の身体感覚に依存している。

Video OS v2 は、そこにAIエージェントを入れようとしたプロジェクトだ。AGIラボのAI Agent Hackathonでファイナリストに残ったこの試みは、単なる自動編集アプリではない。リポジトリの設計文書では、それは「AI video editing app」ではなく、`Editorial Intent Compiler + Media Intelligence OS` と呼ばれている。つまり、素材を読み、編集意図を扱い、候補を出し、構成し、タイムラインへ変換し、レビューし、人間の編集環境へ戻すためのOSである。

出発点にあった問いは、かなり素朴で、かなり深い。

AIの目はどこまで使えるのか。

## 生成ではなく、実素材を見る

作り手が試したかったのは、「AIに絵を作らせる」ことではなかった。むしろ逆で、AIに現実の映像を見せたかった。

動画生成モデルは増えている。プログラムで動画を組む仕組みも増えている。だが、実際の制作現場でつらいのは、いつも生成ではない。撮った素材を見返し、必要な場所を探し、意味のある切り出しに変え、他の素材とつなぎ、音と合わせて一本にすることだ。

人間の編集者は、この作業をかなり曖昧な判断で行っている。「この表情は残したい」「ここは少し長い」「この沈黙は効いている」「BGMが上がるところで絵も上げたい」。それらは一見すると感覚だが、完全な魔法ではない。視線、間、発話、音量、動き、構図、前後関係。分解すれば、いくつもの判断材料がある。

Video OS v2 の実験は、その感覚をプロンプト、ルール、スキル、スコア、ゲートに翻訳することだった。人間が無意識にやっている編集の手つきを、AIが読める形にする。そこに、このプロジェクトの一番面白い部分がある。

ただし、それはAIにすべてを明け渡すことではない。

作り手は「コントロールは人間が持っている感覚を残したかった」と言う。AIの方が早いところは任せたい。大量の素材を見渡す、発話を書き起こす、候補を整理する、BGMのビートを検出する。そこはAIやツールが得意だ。しかし、何を美しいと思うか、何を残したいか、どこで感情を上げるか。その感性は人間側が握りたい。

だから Video OS v2 は、完成動画を吐き出すブラックボックスとして作られていない。構成案、候補、レビュー、タイムライン、XML、各種JSON/YAMLのアーティファクトを残す。エージェントは提案し、決定的なエンジンが変換し、成果物として保存する。チャットの返答ではなく、プロジェクト内の中間成果物が真実になる。

この設計は、AIエージェントを制作現場に入れるうえで重要だ。AIが何となく「いい感じ」に作ったものを受け取るのではなく、なぜそのカットを選んだのか、どのルールでつないだのか、どのゲートを通ったのかを追えるようにする。つまり、「説明できない編集意図で作業させない」ための設計である。

## コンタクトシートというAIのための目

映像をAIに見せるとき、最初にぶつかるのはトークンと時間の壁だ。動画の全フレームを等倍で見せることは現実的ではない。数分の映像でもフレーム数は膨大になる。素材が30本を超えれば、素朴にVLMへ投げるだけで破綻する。

そこで Video OS v2 は、最初に縮小したコンタクトシートで全体を俯瞰する。これは人間の編集者が素材をざっとスクラブし、サムネイルや波形を見ながら当たりをつける行為に近い。AIに全部を見せるのではなく、まず全体の地図を渡す。

そこから必要に応じて深掘りする。候補になりそうな範囲はfilmstripで複数フレームを並べる。動きのあるカットや音楽駆動の素材では、キーフレーム抽出を密にする。静的な会話や説明では、サンプリングを粗くする。`gemini-vlm` の実装には、素材の種類に応じてサンプルFPSやフレーム数を調整する考え方が入っている。`vlm-peak-detector` では、コンタクトシート、filmstrip、dense framesへ段階的に解像度を上げる。

これは単なる節約ではない。AIの視界を設計している。

人間も、素材を見るときに全瞬間を同じ密度では見ていない。動きがありそうなところ、表情が変わるところ、音が立ち上がるところに注意を寄せる。Video OS v2 は、その注意の向け方を処理系に落とし込んでいる。だからここでのVLMは、映像を一枚ずつ説明する装置ではなく、「どこを詳しく見るべきか」を決めるための目でもある。

## 文字で組める映像、絵だけでは難しい映像

このプロジェクトを掘ると、AI編集の得意不得意は「動画」という大きな分類では語れないことがわかる。

インタビューやセミナーは、かなり相性がいい。理由は明快で、文字起こしが編集構成に使えるからだ。何を話しているか、どこに要点があるか、どの発話を残すべきかを、STTが構造化してくれる。話者分離が効けば、誰が話しているかも扱える。すると編集は、映像だけでなく言葉の構成問題になる。

時系列の記録も扱いやすい。子どもの成長記録やイベントの記録では、順番そのものが意味を持つ。素材の中に、ある程度のストーリー構造がすでに入っている。

一方で、絵だけで判断するPV系は難しい。良い絵、エモいカット、使いたい空気感は、必ずしも言語化しやすい特徴として現れない。構図、光、偶然の表情、被写体の存在感。VLMは説明できるが、その説明が編集判断にそのまま使えるとは限らない。

そして未踏の領域として残っているのがMVだ。MVには、インタビューのような発話構造がない。セミナーのような論旨もない。時系列の記録とも違う。音楽のビート、展開、盛り上がり、視覚的な強度を軸に、何をどこへ置くかを決める必要がある。

作り手は「MVはルールなどないからな」と言う。だからこそ面白い。音楽のビートと展開を軸に絵を選んで構成することを、AIはどこまでできるのか。これは Video OS v2 の次の実験になる。

## 編集の手つきをスキルにする

Video OS v2 のリポジトリには、エージェント用のスキルが多い。`design-intent`、`analyze-footage`、`select-clips`、`build-blueprint`、`compile-timeline`、`review-roughcut`、`export-premiere`。これは工程を分けるためのスキルだ。

だが、さらに面白いのは、編集判断そのものもスキル化されていることだ。

`build_to_peak` は、感情やエネルギーをピークへ向けて上げるためのスキルである。`silence_beat` は、沈黙や余韻を扱う。`match_cut_bridge` は、視覚的な類似でカットをつなぐ。`b_roll_bridge` は、発話や文脈の橋渡しとしてBロールを使う。`punch_in_emphasis`、`shot_reverse_reaction`、`reveal_then_payoff` のような名前にも、編集者の手つきがそのまま出ている。

これらは、AIに「いい感じにして」と言うためのものではない。むしろ逆だ。「いい感じ」を分解して、どの観点で判断するかを明示するためにある。

たとえば、会話を中心にしたインタビューと、講義のハイライトと、家族の成長記録では、必要な編集スキルが違う。リポジトリには `interview-highlight`、`lecture-highlight`、`family-growth-recap`、`product-demo`、`vertical-short` といったプロファイルがある。これは「万能の編集AI」を作るよりも、素材と目的に応じて編集の型を切り替える方が現実的だという判断に見える。

ここには、Video OS v2 の思想がよく出ている。AIにセンスを期待するのではなく、センスが働く場所をできるだけ名前にする。名前がつけば、選べる。選べれば、人間がコントロールできる。

## 音に合わせる編集

作り手が特にこだわったのが、音に合わせる編集だった。

映像編集において、BGMはただ後ろで鳴っている音ではない。曲が盛り上がるところで映像も盛り上がる。ビートの頭でカットが決まる。大事な発話のときにはBGMを下げる。最後は全体のラウドネスを整える。こうした処理は、視覚だけでは完結しない。

Video OS v2 には、BGMのビートやセクションを解析する処理がある。`bgm-analyzer` は `librosa`、`aubio`、`ffmpeg` を使い、ビート、ラウドネス、セクション、盛り上がりを見ようとしている。コンパイラ側では、カット位置をビートやダウンビートへ寄せる処理がある。スコアリングでは、BGMの展開やピークとの近さが評価に入る。

さらに、素材音とBGMの関係も扱う。話している内容が重要なところでは、BGMを下げる。`ducking`、`mixer`、`mastering` には、スピーチ区間に応じた音量調整や、最終ミックスのラウドネス正規化が入っている。BGMが映像を盛り上げる一方で、声を殺してはいけない。

このこだわりは、Video OS v2 が「映像を選ぶAI」だけではないことを示している。編集とは、絵を並べるだけではない。音、間、声、盛り上がりを同時に扱う時間設計である。

## モデル選定は、感覚器官を分けること

Video OS v2 では、VLMの選定もかなり試行錯誤されている。APIではGeminiが使われ、ローカル方向ではQwen系やMarlinの統合も検討された。STTではOpenAI系、Groq Whisper、話者分離ではpyannoteが試されている。

ここで重要なのは、万能モデルを一つ探しているわけではないことだ。

Geminiは、フレーム束やコンタクトシートを見る目として機能する。STTは、発話を構造化する耳になる。pyannoteは、誰が話しているかを分ける。MarlinやQwen系の検討は、ローカルで時間方向の映像意味を掴むための実験に近い。

映像編集は、マルチモーダルな判断の連続だ。絵を見るだけでも足りない。言葉を聞くだけでも足りない。音楽のビートだけでも足りない。Video OS v2 は、それぞれのモデルやツールに別の感覚器官を割り当て、それを中間成果物として統合しようとしている。

この設計は、AIエージェント開発としても示唆が大きい。エージェントは一つの巨大な脳である必要はない。むしろ、見る、聞く、測る、構成する、検証する、書き出す、といった役割を分けた方が、失敗箇所を追いやすい。何より、人間が介入しやすい。

## ハッカソンの現実

ただ、構想がきれいだからといって、実装が簡単になるわけではない。

Video OS v2 は、かなり欲張ったプロジェクトだった。インタビューもやりたい。セミナーもやりたい。PVもやりたい。家族の記録も扱いたい。音にも合わせたい。Premiereにも渡したい。アプリ化も見たい。

その結果、素材タイプごとに必要な実装が分かれ、コストが上がった。文字起こしを使える動画と、絵だけで判断する動画では、見るべきものが違う。BGM主導の動画と、発話主導の動画でも、切り方が違う。「全部やろうとしたところ」が、面白さでもあり、詰まりでもあった。

さらに動画は、検証が重い。Web UIなら変更してすぐ画面を確認できる。だが動画編集パイプラインでは、素材解析、候補抽出、構成、タイムラインコンパイル、レンダー、レビューというループを回す必要がある。数分の検証が積み重なる。VLMの待ち時間もある。APIキーやCLIのオプション、zshのglob、キャッシュ、途中再開、進捗表示といった、地味だが避けられない問題も出る。

`roadmap-v2.1` には、ハッカソン後の改善として、プリフライト、VLM解析の並列化、キャッシュ、progress.json、フェーズ単位のコマンド分割、中間プレビュー、BGMビート解析などが並んでいる。これは、デモのための一発芸ではなく、実際に回る制作システムへ近づけようとした痕跡だ。

## チャットからアプリへ

Video OS v2 の先にあるのは、チャットだけで完結する編集体験ではない。

`macos-studio-architecture` では、Video OS Studio は「別の編集エンジン」ではなく、ネイティブなオペレーターサーフェスとして構想されている。素材、解析結果、候補、タイムライン、レビュー、エージェントの状態を、人間が見て操作する画面である。

これは自然な流れだ。映像編集は、テキストだけで確認しにくい。候補カットを見たい。BGMの山を見たい。どの発話が使われたかを見たい。タイムライン上で長さを触りたい。Premiereや他のNLEへ渡したい。

だから、アプリ化は単なるUIの追加ではない。人間がコントロールを取り戻すための場所になる。AIが素材を見て、候補を出し、編集意図をコンパイルする。その結果を、人間が見て、選んで、直す。その往復ができて初めて、AIは制作現場の道具になる。

## AIに感性を明け渡さないために

Video OS v2 を見ていて面白いのは、AIを強く使おうとするほど、人間の感性をどこに残すかが重要になっていることだ。

大量の素材を全部見るのはAIに任せたい。文字起こしも、話者分離も、BGM解析も、ラウドネス調整も任せたい。粗い構成案も出してほしい。だが、「何を残したいか」は人間が握りたい。エモい絵やカットを逃したくない。自分の意思が反映されている感覚を残したい。

この矛盾を、Video OS v2 は矛盾のまま扱っている。

全自動の魔法にしない。すべてを手作業にも戻さない。人間の曖昧な編集意図を、できるだけ説明可能なルールやスキルに変え、AIが得意な速度と網羅性に載せる。そして最後に、もう一度人間が選べるようにする。

AI編集の可能性は、作り手の意思を薄めることではないのかもしれない。むしろ、素材の海に埋もれていた意思を、もう一度取り出しやすくすることにある。

Video OS v2 は、そのためのOSを作ろうとしている。

次に試すべきは、おそらくMVだ。言葉に頼れない。時系列にも頼れない。音楽のビートと展開、絵の強度、空気の連なりだけで構成する。そのときAIの目は、クリエイターの手つきにどこまで近づけるのか。

このプロジェクトの問いは、まだ終わっていない。
