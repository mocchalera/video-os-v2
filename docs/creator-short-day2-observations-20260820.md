## 1. 背景

- ジャンル: 1日のトレーニング vlog（day log）。復活ストーリー（personal challenge）とは別物。
- 素材: iPhone 縦動画13本、本人の生声トーク3本（スタート前61.9s / 湖畔到着27.3s / 完走21.6s）＋ 走行 B-roll。
- 新規アフレコなし。**実発話をそのまま VO として使う**構成。
- 最終尺: 約59秒。

`finish-creator-short` が本来対象としていた DAY0（挑戦宣言・75秒・Triple Crisis 型）とは
素材構成もリテンション設計も異なる。同じ 7-Beat で扱おうとしたのが今回の混乱の原因。

## 2. DAY2 で確定した beat 列（実尺、比率化は Phase 2 で行う）

| # | beat | 実尺 | 内容 |
|---|---|---|---|
| 1 | Double Hook | 0.0–5.0s | ①絶景・衝撃宣言（0.0–2.0s）→ ②疾走アクション（2.0–5.0s）の2段構え |
| 2 | Identity & Gap | 5.0–8.9s | 属性×ギャップの提示 |
| 3 | Environment & Purpose | 8.9–27.0s | 現地環境（気温・標高）＋目的宣言。**この区間は話者の顔に貼り付き、B-roll を連打しない** |
| 4 | Kickoff & B-roll Sprint | 27.0–35.0s | 行動宣言（「行ってきます！」）を合図に B-roll 展開 |
| 5 | Clean HUD & Inner Voice | 35.0–40.0s | データHUD＋心の声テロップ |
| 6 | Apex Freeze | 40.0–43.0s | アクション最高到達点で 1.0〜1.2秒の完全静止＋注釈テロップ |
| 7 | Finish & CTA | 43.0–57.0s | 活動報告＋笑顔の締め |

### 汎用化できる骨格

- **ダブルフック**: 0秒離脱防止を「衝撃宣言」1点に賭けず、2〜5秒に第2のフック（動き）を置く。
- **kickoff アンカー**: 説明トークと B-roll 展開の境界は、beat の位置ではなく
  **行動宣言の発話タイミング**で決まる。これが今回最大の発見。
- **apex freeze**: アクションの最高到達点で静止させ、注釈を置く。
  ユーザーは2回「静止できてないぞ」と差し戻しており、**手作業では再現性が無い**。
- **末尾ノイズトリム**: 発話終了直後の気の緩み（舌出し・疲労表情）を切り、最良の表情で締める。

### 汎用化してはいけないもの（プロジェクト固有 → `STYLE.md` 行き）

- 「富士山めっちゃ綺麗！」「16km」「46歳起業家ランナー」「今日もみんな頑張ろうぜ！」
- 「※わざわざスマホ置いて自撮りしてます笑」という自虐ツッコミのトーン
- キーカラー（`#00E5FF` / `#FF5500` / `#FFE600`）
- 「ペース上げたくなるけど…」等のインナートーク文体

## 3. テロップに関する観測

| 観測 | 汎用/固有 | 備考 |
|---|---|---|
| テロップが声より先に出るとオチがネタバレする | 汎用 | 既存 QA「発話アンカーとのズレ ≤ 1 frame」で表現可能。散文で置き換えないこと |
| 次のテロップ出現前に前行を閉じる（被り防止） | 汎用 | `caption_overlap` 不変条件が既にある（`runtime/caption/final-invariants.ts:167`） |
| 2行テロップの上下マージン `MarginV: 410px / 310px` | **固有** | 1080×1920 決め打ち。汎用化するなら比率かセーフエリア定義に落とす |
| 注釈テロップは主テロップの60〜70%サイズ | 汎用寄り | 階層として妥当。ただし要検証 |
| 背景無依存の二重縁取り＋ソフトシャドウ | 汎用 | 既存の caption style token 側の話 |

## 4. パンチインのガタつき

「カット途中で拡大すると画面とテロップの相対位置がジャンプする」という観測。

repo では zoom は clip 単位のメタデータであり（`runtime/compiler/adjacency.ts:1345`）、
**構造的に mid-clip zoom は発生しない**。これは repo 側で既に解決済みの問題であり、
手作業 ffmpeg 特有の失敗だった。スキルに再掲する必要はない。

## 5. NLE ハンドオフ

Premiere は ASS の装飾・アニメーションを解釈できない。
アルファ付き ProRes 4444（`yuva444p10le`）を V2 用に同梱すれば人間エディタが再現できる、
という発想自体は妥当。ただし **未実装**なので、実装するまでスキルに書かないこと
（Phase 5 で判断）。

なお今回 Premiere が読めなかった XML は、エージェントが python で自作したもの。
repo の `scripts/export-premiere-xml.ts` は使われていない。

## 6. 運用面の発見

- 外出時のレビューは `cockpit ask --media <preview.mp4>` が実際に機能した（v14 / v15 / v18）。
  Phase 7 で手順として固定する。
- 「先に素材を確認した？このストーリーって事実？」— 初回、エージェントは素材を1本も見ずに
  ナレーション原稿を創作した。Whisper 文字起こし後は事実ベースの構成に一変している。
  **素材接地を先に強制する導線**の必要性を示す一次証拠。
